# PRD：长线资金监测 → 小白版每日资金观察日报

日期：2026-08-04 · 状态：待实现 · 模块：market-radar / long_term_capital.py + long-term-capital.yml

## 问题陈述

现有「长线资金监测」每日飞书卡片对零基础用户有四个致命问题：

1. **数据不诚实**：北向资金数据源已停发（2024-08 起交易所停止披露，实测接口返回 0），模块却每天输出"北向: +0.0亿"；回购把"董事会预案金额"（如宁德时代 400 亿）当作已完成回购呈现；估值分位接口报错（JSON 解析失败）且计算后从不展示。
2. **判断不响应数据**：板块分类（见顶/抄底/资金关注）由 2026-07-23 写死的静态文本（QUARTERLY_CONTEXT）驱动——半导体 +6% 或 -6% 输出同一段"见顶"话术；军工电子仅因名字含"电子"即被判见顶。
3. **术语密集且无参照**：超大单、分位、季报背书……零基础用户看不懂；即使看懂数字（如"南向 +25.7 亿"）也没有参照系，无法判断是多是少。
4. **结构误导**：日更数据与季度/周频数据混在同一张卡且无时间标注；卡片日期用运行日期而非数据日期（观察对象当天），跨夜/补跑时读者无法分辨卡片讲的是哪一天的市场。

目标：重做为面向零基础用户的每日资金观察产品——诚实、看得懂、视角中长期、能建立长期认知，并具备自我验证与成长机制。

## 目标用户

零基础股票小白（不了解北向资金、超大单、估值分位等概念）。每日阅读，目标是理解"今天市场资金在做什么、为什么、各方怎么想"（纯认知），不基于此做交易决策。用户本人即首个读者原型。

## 产品定位（底层逻辑）

- **核心价值**：帮助小白建立对市场资金行为的中长期直觉（连续观察 + 解读 + 验证）
- **视角要求**：所有内容带中长期视角——单日信号必须放在持续性、位置（估值）、实名背书的框架里解读，防止读者因单日信号而短视（如看到一天流入就以为是大趋势）
- **差异化**：诚实——没有数据的指标不假装有数据；推断明确标注为推断；数字必须带参照系；判断可被验证
- **红线**：永远不输出针对读者的操作指令（"你要买/建议加仓"）

## 用户故事

1. 作为零基础小白，我希望每天第一眼看到一段大白话总结（≤150 字），以便零知识也能看懂今天发生了什么。
2. 作为零基础小白，我希望每个术语首次出现都附一句人话解释，以便不中断阅读。
3. 作为读者，我希望知道今天哪些板块资金动作最明显、**是谁在买**（机构/大户代理指标 + 季报实名层）、这意味着什么，以便理解市场各方行为。
4. 作为读者，我希望日更数据和长期数据分开、各带时间标签，以便不会误把季度数据当今天的数据。
5. 作为读者，我希望每个资金信号都标注**承接周期**（短期/中期/长期行为，基于持续性、位置、实名背书），以便不会看到单日信号就以为是大趋势。
6. 作为读者，我希望每个数字都有参照系（比平时多/少/正常），以便知道数字的含义。
7. 作为读者，我希望每段分析后有"对你意味着什么"的桥接，以便知道这个信息对自己的意义。
8. 作为读者，我希望卡片日期 = 数据日期（观察对象当天），以便跨夜/补跑时也知道讲的是哪一天的市场。
9. 作为读者，我希望系统定期公布自己判断的对错，以便建立信任。
10. 作为运营者，我希望主数据源失效时收到告警并降级为新闻摘要（而非空转/静默缺块），季度背景过期时收到提示，以便及时修复不误导读者。

## 功能需求

### FR-1 数据修复

- FR-1.1 删除北向行；南向保留并配解释（"内地资金买入港股市场的净额"）。
- FR-1.2 分类判断（见顶/抄底/资金关注/长期建仓等）只由当天数据计算：资金流、涨跌幅、回购、估值。QUARTERLY_CONTEXT 静态文本仅作为"季度背景备注"独立区块展示，不参与分类判定。
- FR-1.3 回购：每笔标注阶段（董事会预案/实施中/完成实施），预案金额与已回购金额分列；删除未实现的假"按行业汇总"功能，改为诚实的个股清单。
- FR-1.4 估值：换可靠数据源修通（实现时实测：东财重试/同花顺/中证指数/ETF 兜底），卡片新增"估值温度"板块展示 PE/PB 5 年历史分位；源不可用时显示"暂无数据"，不静默消失。
- FR-1.5 **观察对象日期规则**（重写）：
  - 卡片顶部日期 = **数据日期**（观察对象当天，从南向 trade_date / 指数 K 线提取），永远不是运行日期
  - 推送判据：**数据日期 > last_pushed_date**（留痕中上次已推送的数据日期）→ 推送并更新；否则跳过（覆盖：跨夜运行不误判、重复触发不重复推、节假日不空转、陈旧缓存被天然挡住）
  - 首次运行（无 last_pushed 记录）→ 允许推送
  - 所有"今天"判断用**北京时间**（GitHub runner 是 UTC，早 8 点前会错一天——已知教训）
  - 不需要维护交易日历：数据日期 == last_pushed → 跳过即为非交易日
- FR-1.6 清理 workflow 死参数（`force`/`weeks` 输入删除或接线）。

### FR-2 日更/长更分离

卡片分两个带时间标签的独立区块：

- 📅 **今日数据**：板块资金流（当日）、南向（当日）
- 🗓️ **长期数据**：估值温度（5 年分位）、回购（近 4 周滚动窗口）、季度背景（标注更新时间）

区块标题固定含"今日"/"近4周"/"季度"字样，从结构上杜绝误读。

### FR-3 资金主体归因与周期判断

- FR-3.1 日频代理归因：超大单（机构代理）vs 大单（大户/游资代理）vs 主力合计；组合信号：价跌+超大单流入 = 逆势吸筹嫌疑，价格大涨+超大单流出 = 出货嫌疑（措辞用"嫌疑"，需连续多日确认才升级表述）。
- FR-3.2 季频实名层：社保/险资/公募持仓（季报），标注披露日期，是唯一"确定谁在买"的数据。
- FR-3.3 诚实声明区块：卡片固定区块一次性说明"资金流是规模推断不是实名、实名持仓每季度更新"，正文不再每句重复限定词。
- FR-3.4 禁止：把代理指标表述为实名（"社保今天在买半导体" = 编造）；不做散户侧归因（无中/小单数据源，已实测确认：当前接口仅主力/超大/大单三档，同花顺接口不存在，旧东财排名接口已死）。
- FR-3.5 **资金承接周期判断**（新增）：每个资金动作板块标注承接倾向三档：
  - **短期行为**：单日脉冲 + 价格位置高 + 无季报/回购背书 → "可能是短期的资金行为，缺乏中长期证据"
  - **中期承接**：量能连续 2-4 日 + 位置中等 + 回购/南向配合 → "有中期承接迹象，需持续确认"
  - **长期布局**：持续流入 + 估值低位/合理 + 季报实名背书或大额回购 → "偏长期布局特征"
  - 数据依据（全部实测可用）：当日资金流（东财 datacenter）、板块 K 线历史量价（1232 天可用）、估值位置（FR-1.4 修通后）、季报实名层、回购
  - 资金流"多日持续性"无现成历史接口（push2 已死）→ **自建留痕**（FR-5），冷启动期（约 2 周）标注"持续性数据积累中"，不硬猜
  - 所有承接判断标注"推断"；措辞用"迹象/特征/倾向"
- FR-3.6 **数字参照系**（新增）：每个资金数字必须配参照标注（vs 近 20 日均值：比平时多/少/正常）；参照数据来自自建留痕（口径一致，2 周后可用）；无法提供参照时必须明确标注"参照积累中"，不得只显示裸数字。

### FR-4 小白解读层（规则保真 + AI 润色）

- FR-4.1 规则层产出"已核验事实清单"（资金最猛/逆势/撤离板块、承接周期、回购大户及阶段、估值温度、南向方向及参照），所有数字只来自实测数据。
- FR-4.2 DeepSeek 基于事实清单生成 ≤150 字每日解读，system prompt 硬约束：只能引用给定事实、禁止编造数字与新闻、禁止操作指令、带中长期视角（单日信号必须放到持续性/位置/背书框架里讲）。
- FR-4.3 AI 失败/超时 → 回退规则模板（同样只填核验过的数字）；模板也失败 → 跳过该板块不崩。
- FR-4.4 术语解释：固定词表（超大单/大单/主力/回购/估值分位/南向等），首次出现附带一句人话。
- FR-4.5 搭桥（强化）：每段分析后接"对你意味着什么"，核心是**今日数据 ↔ 长期背景的连接**（如"今日资金流入方向 vs 季度仓位方向是否一致"）与**承接周期视角**（"单日信号不等于趋势，看持续性"）；禁止空泛的"值得留意"。
- FR-4.6 输出校验：生成后扫描违规措辞（"建议买入/推荐/可以买/加仓/你要"等）→ 整段降级为模板文本。

### FR-5 验证闭环与留痕

- FR-5.1 每日留痕（扩展）：JSONL 记录——分类判断（板块→标签）、当日数据快照（板块资金流、南向、估值）、**last_pushed_date**、数据日期。留痕同时服务：FR-1.5 推送判据、FR-3.5 资金流持续性、FR-3.6 数字参照系。
- FR-5.2 验证：按 10 交易日（半月）/ 20 交易日（月）回放板块实际涨跌，统计"被标资金关注/抄底的板块后续表现 vs 未标注板块"（相关性验证，报告明确标注非因果证明）。
- FR-5.3 报告：半月快报（可选）+ 月报，输出验证统计。
- FR-5.4 调优闭环：某信号**连续两个验证期（每期 20 交易日）无区分度** → 自动降级/移除该分类标签，并记录在报告。

### FR-6 运营保障

- FR-6.1 季度背景过期警告：更新时间 +14 天未更新 → 推送中带"季度背景已过期"警告，直到更新。
- FR-6.2 **三级数据链**（重写）：
  - Level 1 正常：主数据源（东财接口）数据新鲜 → 正常卡片
  - Level 2 降级：交易日但主源失败（指数 K 线当日存在 = 交易日）→ 复用 sources.json + feedparser + RSSHub 多实例，抓财联社/金十/格隆汇当日快讯标题，生成"新闻摘要版"卡片，**显著标注**"⚠️ 数据源暂时不可用，以下为新闻摘要"；只定性（市场方向/大事），**不含精确数字**，不做 AI 解读
  - Level 3 全挂：新闻也失败 → 跳过推送 + 运营告警（连续 2 天触发）
  - 数据陈旧（数据日期 ≤ last_pushed）→ FR-1.5 规则天然跳过
- FR-6.3 全流程无异常：数据、AI、推送任一层失败不阻塞其他层。

## 非功能需求

- **时长**：拉取+生成+推送 ≤ 8 分钟（workflow timeout 10 分钟，给 DeepSeek 留余量）
- **降级不阻塞**：见 FR-4.3 / FR-6.2
- **内容合规**：全卡不出现操作指令；解读不引用未核验的新闻/传闻；正常模式不接新闻源（仅降级模式使用，且只定性不定量）
- **防陈旧/防重复**：卡片日期 = 数据日期；数据日期 ≤ last_pushed → 跳过（FR-1.5）
- **飞书兼容**：emoji 只用飞书支持集合内（有静默回退前车之鉴）
- **成本**：DeepSeek 调用 ≤ 1 次/日（+ 1 次/月验证报告），费用可忽略

## 验收标准

1. 连续运行一周（含至少 1 个节假日）：节假日不推送（数据日期 == last_pushed 时跳过）
2. 卡片任何位置不再出现"北向"数字
3. 用历史数据回放：同一板块在不同资金数据下分类不同（大涨日/大跌日/平盘日文本不同）
4. 解读文本中每个数字可在事实清单中找到对应（抽查 3 天）
5. 估值温度显示真实分位或"暂无数据"，两者必居其一
6. 回购每笔带阶段标注，预案金额与已回购金额分列
7. 模拟 AI key 失效：推送正常发出，解读为模板文本
8. 模拟主源失效（交易日）：收到标注"数据源暂时不可用"的新闻摘要卡；新闻也失败 → 跳过 + 告警
9. 模拟跨夜运行（数据日期 < 运行日）：卡片日期显示数据日期；重复触发不重复推送
10. 每个资金动作板块带承接周期标注（短期/中期/长期 + "推断"）；冷启动期标注"持续性数据积累中"
11. 每个资金数字带参照标注或"参照积累中"
12. 模拟季度背景过期：卡片含过期警告
13. 验证报告输出半月/月两个窗口统计，含调优记录

## 成功指标

- 连续 7 天推送无失败、无静默缺块、无重复推送
- 非金融背景试读 3 天卡片后，能复述"今天资金焦点在哪、是谁在买、承接是短期还是中长期、为什么"
- 月报发布后，信号分类依据报告至少调整过一次（证明闭环在工作）

## 不在范围内

- 针对读者的买卖/操作指令（硬红线）
- 个股深度解剖（个股仅限回购名单 + 领涨股的知识性解读）
- 严格信号回测（改为 FR-5 验证闭环）
- 正常模式下的新闻/政策源接入（仅降级模式做定性兜底；"为什么"仍限数据层面因果）
- 散户侧资金归因（无数据源）
- 板块异动模块（sector_monitor.py）改动
- 多平台分发（仍走飞书卡片）
- 真实用户运营（打开率、留存等后续阶段）
